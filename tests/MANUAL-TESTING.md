# Ручна перевірка модуля перед релізом

Для того, хто перевіряє гілку `dev` до виходу 1.0.0. Як модуль налаштовується, описано в
[README](../README.md). Тут описано, що перевірити і як не нашкодити.

## Перш ніж почати

- **Не перевіряйте на робочому магазині.** Модуль створює справжні накладні в Новій Пошті,
  а магазин надсилає листи й повідомлення про замовлення. Візьміть копію чи чистий
  OkayCMS 4.5.3 або [форк](https://github.com/devSviat/OkayCMS-Fork) на PHP 8.5.
- **Ключ API — з вашого бізнес-кабінету НП.** Створені накладні справжні: після перевірки
  видаліть їх (кнопка «Видалити накладну» в замовленні). Видалити можна, поки посилку не
  передали Новій Пошті.
- **У тестових замовленнях лише ваші контакти:** свій телефон і пошта або вигадані.

## Встановлення з гілки dev

```sh
cd /шлях/до/сайту/Okay/Modules
mkdir -p Sviat
git clone -b dev https://github.com/devSviat/NovaPoshta-OkayCMS.git Sviat/NovaPoshta
```

Або завантажте ZIP гілки `dev` на GitHub і розпакуйте його так, щоб вийшов каталог
`Okay/Modules/Sviat/NovaPoshta`. Далі робіть як у README, розділ «Встановлення», з пункту 2.

Планувальник потрібен: без нього не завантажаться довідники й не оновляться статуси. Якщо
cron не налаштований, запускайте задачі вручну:

```sh
php ok scheduler:list          # номери задач Nova Poshta
php ok scheduler:task -f <номер>
```

Запускайте від того користувача, від якого працює сайт (наприклад, `www-data`). Інакше
кеш і скомпільовані шаблони стануть чужими, і сайт відповідатиме помилкою 500.

## Що перевірити

Позначайте пункти, які пройшли. Якщо щось пішло не так, опишіть, як це повторити (див.
«Як повідомити про помилку»).

### Налаштування (Модулі → Мої модулі → Nova Poshta)

- [ ] **Ключ API:** «Зберегти й перевірити» показує, що ключ працює з обома API. Неправильний
      ключ дає зрозуміле пояснення, що робити.
- [ ] **Довідники:** «Оновити зараз» → за кілька хвилин (після запуску планувальника) блок
      показує кількість пунктів і населених пунктів.
- [ ] **Відправлення й розрахунок ціни:** вибір міста й відділення відправника, вага й
      об'єм за замовчуванням, помилки на некоректних значеннях.
- [ ] **Вкладка «Пункти видачі»:** групи пунктів і кнопки популярних міст зберігаються й
      видні в кошику.
- [ ] **Вкладка «Накладні та післяплата»:** контактна особа й телефон відправника,
      значення форми накладної.
- [ ] Сторінка налаштувань на телефоні читається й не має горизонтальної прокрутки.

### Способи доставки й оплати

- [ ] Два способи доставки з модулем Nova Poshta: «Відділення або поштомат» і «Адреса
      (кур'єр до дверей)».
- [ ] «Безкоштовна від 0» у способі доставки показує червоне попередження.
- [ ] У способі оплати позначка «Післяплата Нової Пошти»: грошовий переказ або контроль
      оплати (контроль працює лише з договором NovaPay).
- [ ] У варіанті товару є поле «Об'єм, м³» з підказкою, і воно зберігається.

### Кошик

- [ ] Пошук міста за початком назви і з тезками (село й місто з однаковою назвою). Кнопки
      популярних міст працюють.
- [ ] Список відділень і поштоматів великого міста (Київ) завантажується швидко, пошук за
      номером і вулицею працює, графік роботи видно.
- [ ] Після вибору пункту з'являються ціна доставки й підсумок. Під післяплатою видно
      комісію за переказ.
- [ ] Важкий, великий або дорогий товар (задайте вагу й об'єм варіанту): пункти, які його
      не приймуть, позначені «Не вміщається…» чи «Не підходить…», а оформити замовлення
      туди не можна.
- [ ] Адресна доставка: пошук вулиці, будинок, квартира, підйом на поверх (якщо його
      увімкнено в налаштуваннях).
- [ ] Оформлення без пункту чи міста не проходить, і видно, що виправити.
- [ ] Оформлене замовлення зберігає пункт або адресу й ціну, яку показував кошик.
- [ ] Кошик на телефоні.

### Замовлення в адмінці

- [ ] Картка замовлення показує місто й пункт (або адресу). Посилання «змінити» дає
      вибрати інший пункт.
- [ ] **Створити накладну** з форми: з післяплатою і без, у відділення, у поштомат і на
      адресу. Після створення видно номер, статус і план доставки.
- [ ] Номер накладної копіюється, посилання відкриває трекінг на сайті НП.
- [ ] «Оновити» в картці накладної підтягує свіжий статус.
- [ ] **Видалити накладну:** вона зникає з замовлення, а в кабінеті НП стає «Видалена»
      (НП показує це із затримкою до хвилини).
- [ ] **Прив'язати** накладну, створену вручну в кабінеті НП, за 14-значним номером.
      Чужий або видалений номер дає зрозумілу відмову.
- [ ] **Список замовлень:** колонка з номером і статусом НП, фільтр «Статус НП», пошук за
      номером накладної.
- [ ] **Масово:** позначте кілька замовлень → дія «Створити накладні Нової Пошти» → звіт
      «створено N з M» з причиною для кожного пропущеного. Потім видаліть створені накладні.
- [ ] Статуси накладних оновлюються задачею трекінгу (раз на 15 хв або вручну).

### Перехід зі старих модулів

Лише якщо є копія магазину з `NovaposhtaCost`, `NovaPoshtaTracking` чи
`NovaPoshtaPopularCities`. Кроки описано в README, розділ «Перехід зі старих модулів».

- [ ] Блок переходу з'являється і показує, скільки замовлень і накладних знайдено.
- [ ] Після перенесення старі замовлення показують пункт і накладну в новому модулі, а
      незіставлені просять вибрати пункт заново.
- [ ] «Перенести ще раз» не дублює вже перенесене.

## Це не помилки

- Одразу після створення накладної з післяплатою в картці може бути сірий рядок «Платника
  комісії за переказ Нова Пошта показує не одразу». Перші секунди НП повертає платника
  за замовчуванням.
- Для накладної, створеної через новий API, пункт видачі НП показує трохи пізніше; про це
  є такий самий сірий рядок.
- Якщо Нова Пошта не відповідає, кошик показує ціну способу доставки, а замовлення
  оформлюється далі.

## Як повідомити про помилку

Відкрийте [issue](https://github.com/devSviat/NovaPoshta-OkayCMS/issues) і додайте:

- OkayCMS 4.5.3 чи форк, версію PHP;
- кроки, щоб повторити, і що очікували побачити;
- знімок екрана;
- рядки з `Okay/log/app-*.log` за той час (SQL-помилки пишуться лише туди);
- для накладної: текст помилки з картки. Ключ API, телефони й імена покупців не додавайте.

## Після перевірки

- Видаліть усі створені накладні (у списку замовлень фільтр «Статус НП» → «Створено»).
- Перевірте в кабінеті НП, що вони мають статус «Видалена».
